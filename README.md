# SpecGuard AI — Requirements Quality Gate

CLI проверяет банковское ТЗ перед передачей в разработку и QA. Для демонстрации откройте HTML-отчёт в браузере. В каждой карточке указаны основание, бизнес-последствие, источник и вопрос аналитику. Тот же результат можно сохранить в JSON.

## Установка и запуск

Нужен Python 3.11+ и PDF с текстовым слоем, Markdown или TXT в UTF-8. Из корня проекта в PowerShell:

```powershell
py -m venv .venv
.\.venv\Scripts\python -m pip install .
$env:GEMINI_MODEL = 'gemini-3.5-flash'
$env:GEMINI_API_KEY = [System.Net.NetworkCredential]::new('', (Read-Host 'Gemini API key' -AsSecureString)).Password
.\.venv\Scripts\specguard validate input.pdf --allow-cloud --verify --output reports/review.json
.\.venv\Scripts\specguard render reports/review.json --output reports/review.html
```

Gemini выполняет смысловой анализ, Python извлекает исходные строки, проверяет ссылки, сопоставляет ограничения и рассчитывает решение. JSON содержит полный исходный текст, храните отчёты в пределах разрешённого контура.

Для варианта с Gemini получите ключ в [Google AI Studio](https://aistudio.google.com/apikey). Задайте в текущем процессе `GEMINI_API_KEY` и `GEMINI_MODEL`. Названия переменных приведены в .env.example. Команда с явным согласием на передачу документа:

```powershell
.\.venv\Scripts\specguard validate input.pdf --allow-cloud --output reports/review.md
```

Без параметра модели CLI проверяет файл локальными правилами. При сбое модели получается частичный отчёт и код 2. Ошибка чтения или записи даёт код 1. Код 0 означает успешный запуск выбранного режима. Решение о готовности находится внутри отчёта.

Параметр `--verify` добавляет один запрос к той же модели Gemini, когда есть кандидаты на замечания. В запрос входят выводы, сценарии и процитированные строки. Поле `verification` в JSON хранит решения с обоснованиями. При сбое повторной проверки CLI сохраняет требования и результаты правил с кодом 2.

## Как читать результат

1. **Паспорт** связывает файл, модель и сборку с конкретным прогоном.
2. **Карта** сопоставляет внутренний ID, исходный ID, формулировку и строку. Координаты P2L5 означают пятую строку извлечённого текста второй страницы. Нарезка по структуре документа эвристическая. Для PDF с колонками требуется сверка порядка чтения. OCR пока отсутствует.
3. **Проверка набора** ищет несовместимые интервалы, несогласованные даты в примерах, изменение состояния через GET и открытые вопросы. Отдельные правила оценивают измеримость. Смысловые вопросы модели сопровождаются цитатами из исходника и требуют решения аналитика.
4. **Решение** BLOCKED означает обнаруженное несовместимое ограничение. REVIEW требует разбора находок, неполного покрытия или сбоя модели. READY допускается при завершённой проверке, наличии выделенных требований и отсутствии замечаний. Владелец продукта принимает итоговое решение.

## Воспроизводимая проверка

В версии 0.2.0 карта показывает отдельную очередь строк вне нарезки, включая нераспознанные формулировки и контекст. Наличие таких строк требует ручной проверки перед READY. Координаты охвата относятся к строкам извлечённого текста; полнота смысла нескольких условий на одной строке остаётся предметом ревью. Сравнение числовых ограничений учитывает полную иерархию разделов и приводит явные длительности к секундам (сутки = 24 часа).

```powershell
.\.venv\Scripts\python -m unittest discover -s tests
.\.venv\Scripts\python benchmark.py --output reports/rules.json
.\.venv\Scripts\python benchmark.py --allow-cloud --output reports/gemini-baseline.json
.\.venv\Scripts\python benchmark.py --allow-cloud --hybrid --output reports/gemini-hybrid.json
```

Девять коротких синтетических спецификаций проверяют регрессию, включая корректные примеры. Для правил учитываются категория и набор строк. При сравнении baseline и hybrid используется один критерий — точное совпадение набора строк. Совпадение строк само по себе не подтверждает смысл вывода. Для оценки работы аналитика нужна отдельная слепая разметка замечаний и замер времени с учётом ручного подтверждения.

Официальный вход и автоматически сформированный отчёт сдавайте рядом со ссылкой на проект. Веса модели и API-ключ в репозиторий не входят. [Задание организаторов](https://github.com/BCC-HUB/ai-requirements-validator-task).
