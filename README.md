# SpecGuard AI — Requirements Quality Gate

CLI проверяет банковское ТЗ перед передачей в разработку и QA. Для демонстрации откройте HTML-отчёт в браузере. В каждой карточке указаны основание, бизнес-последствие, источник и вопрос аналитику. Тот же результат можно сохранить в JSON.

Версия 0.5.0. [Пример отчёта об исправлении](docs/EXAMPLE_COMPARISON.md) · [Устройство проверки](docs/ARCHITECTURE.md) · [Сценарий защиты](docs/DEMO.md).

## Установка и запуск

Нужен Python 3.11+ и PDF с текстовым слоем, Markdown или TXT в UTF-8. Из корня проекта в PowerShell:

```powershell
py -m venv .venv
.\.venv\Scripts\python -m pip install .
$env:GEMINI_MODEL = 'gemini-3.5-flash'
$env:GEMINI_API_KEY = [System.Net.NetworkCredential]::new('', (Read-Host 'Gemini API key' -AsSecureString)).Password
.\.venv\Scripts\specguard validate input.pdf --allow-cloud --verify --output reports/review.json
.\.venv\Scripts\specguard render reports/review.json --output reports/review.html
```

Gemini выполняет смысловой анализ, Python извлекает исходные строки, проверяет ссылки, сопоставляет ограничения и рассчитывает решение. JSON содержит полный исходный текст, храните отчёты в пределах разрешённого контура.

Для варианта с Gemini получите ключ в [Google AI Studio](https://aistudio.google.com/apikey). Задайте в текущем процессе `GEMINI_API_KEY` и `GEMINI_MODEL`. Названия переменных приведены в .env.example. Команда с явным согласием на передачу документа:

```powershell
.\.venv\Scripts\specguard validate input.pdf --allow-cloud --output reports/review.md
```

Без `--allow-cloud` CLI выполняет диагностику правилами, без сетевых запросов. Для полной проверки требуется Gemini. При сбое модели агент сохраняет частичный отчёт с кодом 2 и названием этапа. Ошибка чтения или записи даёт код 1. Код 0 означает успешный запуск выбранного режима. Решение о готовности документа находится внутри отчёта.

Параметр `--verify` добавляет один запрос к той же модели Gemini, когда есть кандидаты на замечания. В запрос входят выводы, сценарии и процитированные строки. Поле `verification` в JSON хранит решения с обоснованиями. При сбое повторной проверки CLI сохраняет требования и результаты правил с кодом 2.

## Как читать результат

1. **Паспорт** связывает файл, модель и сборку с конкретным прогоном.
2. **Карта** сопоставляет внутренний ID, исходный ID, формулировку и строку. Координаты P2L5 означают пятую строку извлечённого текста второй страницы. Нарезка по структуре документа эвристическая. Для PDF с колонками требуется сверка порядка чтения. OCR пока отсутствует.
3. **Проверка набора** ищет несовместимые интервалы, несогласованные даты в примерах, изменение состояния через GET и открытые вопросы. Отдельные правила оценивают измеримость. Смысловые вопросы модели сопровождаются цитатами из исходника и требуют решения аналитика.
4. **Решение** BLOCKED означает доказанное противоречие границ. Для READY нужны завершённый смысловой проход, полное текстовое покрытие выделенных формулировок, отсутствие строк вне карты, замечаний и открытых оценок. В остальных случаях требуется REVIEW. Статус относится к выполненным проверкам. Нужность требования и соответствие бизнес-политике часто может подтвердить только владелец.

## Воспроизводимая проверка

Начиная с 0.4.0 карта сохраняет исходные предложения даже при пропуске одного из них моделью. При неполной цитате строка уходит на сверку. Семантическая полнота нескольких действий внутри одного предложения остаётся предметом ревью. Результат для набора и девяти индивидуальных критериев хранится в JSON вместе с основаниями. Явная ссылка на уникальный ID требования в критерии приёмки создаёт ребро `acceptance_reference`.

```powershell
.\.venv\Scripts\python -m unittest discover -s tests
.\.venv\Scripts\python benchmark.py --output reports/rules.json
.\.venv\Scripts\python benchmark.py --allow-cloud --output reports/gemini-baseline.json
.\.venv\Scripts\python benchmark.py --allow-cloud --hybrid --output reports/gemini-hybrid.json
```

Benchmark содержит 17 синтетических документов. Параметр `--suite core|transfer|all` выбирает девять исходных, восемь дополнительных или все примеры. Для обоих облачных профилей и правил сравниваются категория и строки, определяющие дефект. Повторная карточка считается лишним срабатыванием. При сбое хотя бы одного документа серия получает INCOMPLETE, код 2 и пустые итоговые precision/recall. Корпус открыт разработчикам. Оценка переноса на новые банковские документы требует отдельной слепой разметки.

Официальный вход и автоматически сформированный отчёт сдавайте рядом со ссылкой на проект. Веса модели и API-ключ в репозиторий не входят. [Задание организаторов](https://github.com/BCC-HUB/ai-requirements-validator-task).

## Как проверить правку владельца

Сравнение проверяет две редакции одинаковыми правилами без сетевых вызовов. В примере про квитанции старый интервал пуст: минимум 72 часа, максимум сутки. После правки агент находит допустимое значение 24 часа и показывает обе пары цитат. Такой вывод относится к конкретной паре условий. Удаление строки, смена предмета или неоднозначный ID отправляют прежнее замечание на ручную сверку.

```powershell
.\.venv\Scripts\specguard compare examples/retention/before.md examples/retention/after.md --output reports/changes.html
```

Для календарного примера агент сопоставляет правило, исходные условия и действие в таблице. Автоматическое подтверждение возможно, когда изменился ожидаемый месяц и новое значение совпало с правилом. Форматы отчёта сравнения — HTML, Markdown и JSON. Сохранённый JSON можно повторно оформить командой `render`.

## Комплект для сдачи

Для нового прогона по официальному файлу достаточно одной команды из корня проекта. Флаг разрешает отправку документа в Gemini и повторную сверку замечаний. В интерактивном терминале при отсутствии переменной ключ вводится со скрытым вводом. По умолчанию используется модель из примера конфигурации. При отказе сети или модели CLI возвращает код 2 и сохраняет частичный JSON для диагностики. Готовый ZIP обновляется только после успешных проверок.

Если Gemini вернул HTTP 503, агент делает максимум одну дополнительную попытку на этапе. Обычная пауза — две секунды. Числовой Retry-After до 15 секунд задаёт паузу провайдера, при более долгом ожидании запуск завершается с диагностикой. Попытки перечислены в `llm_calls`.

```powershell
.\.venv\Scripts\python package_submission.py reports/requirements.md --allow-cloud --output reports/v0.5.0/SpecGuard-BCC.zip
```

Для сборки комплекта используйте тот же файл входа и JSON успешного прогона с `--verify`. Команда сверяет отпечатки движка и документа, координаты и цитаты. В ZIP попадут исходники, исходный документ, JSON и читаемый HTML.

```powershell
.\.venv\Scripts\python package_submission.py reports/requirements.md reports/v0.5.0/verified.json --output reports/v0.5.0/SpecGuard-BCC.zip
```
