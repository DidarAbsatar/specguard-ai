# Демонстрация для жюри

Откройте HTML, построенный командой `specguard render` из JSON выбранного прогона BCC. Покажите в паспорте имя модели, отпечаток входа, версию агента и статус сверки. Для версии 0.4.0 используйте `reports/v0.4.0/verified.json`, если его паспорт подтверждает завершённый облачный прогон. Сохранённый облачный результат 0.3.0 находится в `reports/v0.3.0/audited/review.html`.

**1 минута — решение аналитика.** Откройте карточку календарного примера. Прочитайте дату покупки, дату проведения и ожидаемый счётчик. Сопоставьте с правилом выбора месяца. Владелец продукта должен решить, какой месяц верен. После согласования QA сможет однозначно проверить пограничный случай.

**1 минута — устройство проверки.** Покажите обе цитаты и координаты. Gemini извлекает смысловые замечания, правила связывают условие с примером. Для прогона с флагом `--verify` откройте массив verification в JSON и покажите решение по конкретной цитате.

**1 минута — решение владельца и повторная проверка.** Откройте независимый пример про квитанцию. После 24 часов первая команда потребует хранить её ещё 48 часов, вторая допускает хранение максимум сутки. В учебном сценарии владелец согласовал сутки. Два запуска через обычный CLI показывают смену числа конфликтов и сохраняют связь с критерием приёмки.

```powershell
.\.venv\Scripts\specguard validate examples/retention/before.md --output reports/retention-before.html
.\.venv\Scripts\specguard validate examples/retention/after.md --output reports/retention-after.html
```

В первом отчёте найдите BLOCKED, контрпример и ссылки на обе строки. Во втором числовой конфликт снят. В диагностике правилами итог остаётся REVIEW до смысловой проверки. В разделе критериев набора откройте ссылку на RC-1. Выбор суток иллюстрирует решение учебного владельца.

**1 минута — проверка качества.** Откройте metrics из запуска `benchmark.py --suite all`. Единица совпадения — категория и строки размеченного дефекта. Покажите один положительный и один отрицательный пример из массива cases. Облачное сравнение допустимо только для двух завершённых серий на одном корпусе. Для промышленного пилота нужны новые документы и независимый аналитик.

**1 минута — ценность.** Покажите, какое решение должен принять владелец до разработки и какой тест изменится вслед за ним. Предложите пилот с замером времени ручного ревью, времени перепроверки отчёта и доли замечаний, принятых аналитиками. Денежный эффект можно посчитать после получения этих данных.

**Как измерить эффект пилота.** Два аналитика получают сопоставимые документы. Для половины документов первый работает с отчётом, второй вручную, для другой половины порядок меняется. Засеките минуты от открытия ТЗ до согласованного списка вопросов, включая отбраковку ложных сигналов. Третий специалист без указания метода сводит дубли и подтверждает дефекты. Сравните медиану времени и число верно выявленных критичных дефектов на документ. Источник тарифов и стоимость API фиксируются отдельно, если появятся расходы.
