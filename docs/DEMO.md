# Демонстрация для жюри

Откройте сгенерированный submission.html. Покажите в паспорте имя модели, отпечаток входа и длительность именно этого запуска. Для живого прогона используйте команду из README с официальным requirements.md.

**1 минута — решение аналитика.** Откройте карточку календарного примера. Прочитайте дату покупки, дату проведения и ожидаемый счётчик. Сопоставьте с правилом выбора месяца. Владелец продукта должен решить, какой месяц верен. После согласования QA сможет однозначно проверить пограничный случай.

**1 минута — устройство проверки.** Покажите обе цитаты и координаты. Объясните, как правила связывают условие с примером, а локальная языковая модель проверяет смысл документа. Откройте массив verification в JSON. В нём сохранены исходные кандидаты модели и решения повторной проверки.

**1 минута — защита от переобучения.** Запустите тест связи лимита за период с повторным триггером на примере выдачи талона. В тесте календарного конфликта измените ожидаемый месяц на согласованный и покажите исчезновение замечания.

**1 минута — проверка качества.** Покажите число документов, истинные и ложные срабатывания и пропуски. Единица совпадения для сравнения моделей — набор строк с размеченным дефектом. Это малая регрессионная выборка разработчиков. Для промышленного пилота нужны новые документы и независимый аналитик.

**1 минута — ценность.** Покажите, какое решение должен принять владелец до разработки и какой тест изменится вслед за ним. Предложите пилот с замером времени ручного ревью, времени перепроверки отчёта и доли замечаний, принятых аналитиками. Денежный эффект можно посчитать после получения этих данных.
